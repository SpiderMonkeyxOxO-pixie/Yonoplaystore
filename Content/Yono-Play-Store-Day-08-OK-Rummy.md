## Does the Android identity match?

An APK filename can be changed easily. Stronger identity signals include the label shown by Android, package name and signing identity.

Before installing, compare the source-page name with the installer. If the file is presented as an update, it should preserve the expected package and signer. Pause if it installs as a second app, unexpectedly replaces another package or requires the current app to be removed without a clear explanation.

Use the same three states:

- **Continue:** App label, package and signer match the expected record.
- **Verify:** Version or file-size information is missing, but the source provides a credible way to confirm it.
- **Stop:** The installer shows another name, the package differs or an alleged update conflicts with the existing signer.

Do not uninstall an existing app merely to bypass an Android warning. First determine what changed.

## Are the requested permissions proportionate?

A permission should support a feature the user deliberately opens. Notifications may be optional for account or service alerts. Camera or photo access may make sense during a user-initiated profile or document step.

Contacts, SMS, call logs, continuous location, broad storage, accessibility control and device administration require stronger explanations. Permission timing matters: a request made during a relevant task is easier to understand than the same request appearing before the app explains any feature.

Choose:

- **Continue** when the purpose is clear and access is limited to the feature.
- **Verify** by denying the permission and checking whether the app still provides normal functions.
- **Stop** when screen control, remote-access software or disabled security settings are demanded.

The [App Safety checklist](/app-safety/) helps evaluate Android access alongside account data and payments.

## How should OK Rummy support behave?

Support behavior is part of the safety review. A usable support route should identify the service, keep a written complaint record and solve ordinary issues without asking for authentication secrets.

Never disclose an OTP, UPI PIN, card PIN, device unlock code or recovery credential. Do not install screen-sharing software or grant accessibility access so a support contact can control the phone.

Continue when support uses the documented channel and asks only for ordinary references such as a user ID or transaction number. Verify when the contact moves to a new channel but can explain and confirm the change through the official site. Stop when someone pressures you, guarantees an outcome or asks for another payment to unlock a withdrawal or account.

## What should you check before paying?

Read the current account, payment and withdrawal terms before depositing. Separate:

- Money the user deposits.
- Promotional credits governed by conditions.
- Rewards displayed inside the app.
- A balance that the terms define as eligible for withdrawal.

These amounts can follow different minimums, verification requirements, fees and processing times. A displayed balance is not automatically withdrawable money.

Confirm that the named payment recipient is consistent with the operator described in the terms. Stop if payment is requested to a changing personal account, if a private contact promises guaranteed winnings or if an extra fee is demanded only after a withdrawal is requested.
