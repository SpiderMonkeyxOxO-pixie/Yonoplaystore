## Why are numbered-app names difficult to verify?

Numbers are reusable and rarely identify an operator by themselves. A domain may add a number for versioning, marketing, routing or another unknown reason. A filename may include a year or build number. None of those patterns independently proves that two sources distribute the same app.

Use a four-part identity string:

**Exact name + final domain + Android package + signing identity**

That combination is more useful than an icon, filename or referral code. If one part changes, record the change rather than assuming it is harmless.

## Which Android details identify 101Z?

An APK filename can be renamed, so `101Z.apk` is not identity proof. Compare the installer label, package name and signing identity.

If a file is presented as an update, it should preserve the expected package and signer. Stop when it installs as a second app, replaces an unrelated package or requires the current installation to be deleted without explaining the change.

Also record the version, file size and stated date when available. These fields do not prove safety, but inconsistencies can reveal that two download pages are distributing different files under the same short name.

Keep Play Protect enabled. Do not disable Android safeguards merely because a file or message uses the correct 101Z spelling.

## Which permissions should be reviewed?

Every permission should support a feature the user deliberately opens. Network access and optional notifications may be understandable for a connected app. Camera or selected-photo access may be relevant during a user-initiated profile or document step.

Contacts, SMS, continuous location, broad storage, accessibility control and device administration require stronger explanations. Deny unclear access and check whether normal features still work.

Never grant screen-reading or remote-control access to a private contact offering installation, account or payment help. The [App Safety checklist](/app-safety/) combines permissions with data and payment warnings.

## What should you check before registering or paying?

Read the privacy policy and account terms on the final domain. They should identify the organization handling personal data, explain collection and retention and provide account-closure and complaint procedures.

Never share an OTP, UPI PIN, card PIN, device unlock code or remote-control access with support. Ordinary account assistance should use a ticket, user ID or transaction reference without authentication secrets.

If the app shows credits, rewards or balances, find their definitions before treating them as money. Check eligibility, identity verification, minimums, fees, processing times and location restrictions. A short numeric brand or large displayed balance does not prove a withdrawal outcome.
